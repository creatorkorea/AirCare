# AirCare Redesign System

## 리뉴얼 방향

AirCare 리뉴얼은 카드가 많은 정보형 랜딩이 아니라, 큰 장면을 따라 스크롤하며 신뢰를 쌓는 원페이지 서비스 사이트를 목표로 한다.

핵심 인상은 다음 한 문장으로 정리한다.

> 전문 기사가 에어컨 속까지 분해해 깨끗한 바람을 만들어주는 믿을 수 있는 홈케어 서비스

## 디자인 키워드

- 깨끗함: 흰색, 쿨 그레이, 선명한 실제 작업 이미지 중심
- 전문성: 큰 타이포그래피, 명확한 정보 위계, 과장 없는 문장
- 신뢰감: Before/After, 작업 과정, 가격, 지역, 후기의 투명한 노출
- 시원함: 블루 CTA와 민트 액센트로 공기감 표현
- 친절함: 모바일에서 바로 예약할 수 있는 단순한 흐름

## 시각 방향

### 선택한 방향

프리미엄 로컬 홈케어 에디토리얼 랜딩.

### 피해야 할 방향

- SaaS 대시보드처럼 작은 카드가 빽빽한 첫 화면
- 추상 그라디언트나 장식용 도형 위주의 히어로
- 어둡고 흐릿한 스톡 이미지
- 너무 많은 pill, badge, floating card
- 섹션 안에 카드가 중첩되는 구조
- 한 가지 파란색만 반복되는 단조로운 팔레트

## 레이아웃 원칙

### 원페이지 스크롤

- 각 주요 섹션은 한 화면에 가깝게 크게 보이도록 구성한다.
- 섹션은 카드 묶음이 아니라 전체 폭 band 또는 큰 이미지/타이포 조합으로 만든다.
- 첫 화면에서는 다음 섹션의 일부가 보이게 해 스크롤 흐름을 만든다.
- 반복 정보만 카드로 쓴다. 예: 후기, 가격 항목, FAQ, 서비스 종류.

### 섹션별 밀도

- Hero: 정보 최소화. 큰 이미지, 큰 제목, CTA, 3개 이하 신뢰 지표.
- Problem: 고객의 문제를 큰 문장과 실제 오염 이미지로 보여준다.
- Solution: 작업 방식과 장비를 단계적으로 설명하되 카드 수를 제한한다.
- Before/After: 작은 썸네일이 아니라 넓은 비교 이미지 중심.
- Price: 카드보다 표나 가격 band를 우선한다.
- Process: 큰 숫자 타임라인으로 한눈에 보이게 한다.
- Reviews: 반복 카드 허용. 단, 화면에 보이는 카드 수를 제한한다.
- FAQ: 아코디언 허용. 질문 문장은 실제 고객 언어로 작성한다.

## 타이포그래피

### 폰트

- 기본 폰트: Pretendard
- 대체 폰트: Noto Sans KR
- 시스템 대체: Apple SD Gothic Neo, system-ui, sans-serif

### 계층

- Hero H1: 44-68px desktop, 34-42px mobile
- Section H2: 34-48px desktop, 26-34px mobile
- Body: 15-18px desktop, 14-16px mobile
- Caption/Meta: 12-14px

### 규칙

- letter-spacing은 0을 유지한다.
- 한글 제목은 억지로 자간을 줄이지 않는다.
- 모바일에서는 줄바꿈을 의도적으로 짧게 만든다.
- 제목은 굵게, 본문은 편하게 읽히는 굵기로 둔다.

## 색상 토큰

```css
--blue: #075fe4;
--blue-dark: #064bb5;
--navy: #071a33;
--ink: #10233f;
--muted: #66758a;
--line: #dfe8f2;
--ice: #f3f8fd;
--mist: #eef8f8;
--mint: #12a987;
--warm: #f6a623;
--white: #ffffff;
```

### 사용 규칙

- Primary CTA는 `--blue`만 사용한다.
- 민트는 청결, 친환경, 확인 상태에만 제한적으로 쓴다.
- 배경은 흰색과 쿨 그레이 계열을 번갈아 사용한다.
- 경고/마감/예약 안내가 필요할 때만 warm 색상을 쓴다.

## 이미지 규칙

- 실제 작업 사진을 우선한다.
- 히어로 이미지는 서비스 장면을 크게 보여준다.
- 에어컨 내부, 세척 과정, Before/After는 선명해야 한다.
- 고객이 결과를 확인해야 하는 이미지는 어둡게 덮지 않는다.
- 텍스트 가독성을 위한 overlay는 히어로에만 제한적으로 사용한다.

## 버튼과 CTA

### Primary CTA

- 문구: 예약 상담하기, 지금 예약하기
- 색상: blue background, white text
- 높이: mobile 50px 이상, desktop 48px 이상
- radius: 8px 이하

### Secondary CTA

- 문구: 가격 보기, 작업 사례 보기
- 버튼보다 링크에 가깝게 가볍게 처리한다.

### 모바일 CTA

- 모바일에는 하단 고정 예약 버튼을 유지한다.
- 첫 화면 안에 CTA가 한 번, 하단 고정 CTA가 한 번 보이도록 한다.

## 카드 사용 규칙

카드는 반복 정보에만 사용한다.

허용:

- 후기 카드
- FAQ item
- 서비스 종류 item
- 가격 항목
- 예약 모달 내부 입력 패널

제한:

- 히어로 안의 floating price card
- 히어로 안의 다중 정보 카드
- 섹션 전체를 감싸는 큰 카드
- 카드 안에 또 다른 카드

## 모션 규칙

- 스크롤은 부드럽게 유지한다.
- 메뉴, FAQ, 예약 모달은 즉각 반응한다.
- 대형 섹션 전환에는 fade/slide 정도만 사용한다.
- 핵심 CTA는 hover/focus 상태가 명확해야 한다.

## 접근성 규칙

- 모든 버튼에는 명확한 텍스트 또는 접근 가능한 이름을 둔다.
- 모바일 메뉴 `aria-expanded`를 유지한다.
- FAQ `aria-expanded`를 유지한다.
- 배경 이미지 위 텍스트는 충분한 대비를 확보한다.
- 키보드 포커스 스타일을 제거하지 않는다.

## 구현 순서

4. Price

6. Reviews
